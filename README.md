## تحديث تجريبي 0.2.8 — تمييز حركات البصمة (31 أكتوبر 2026)
- **أخضر:** حضور أولي. **أحمر:** انصراف نهائي. **برتقالي:** خروج مؤقت وعودة مرتبطة به (استعذار أثناء الدوام). الحركة غير المؤكدة تظهر بلون محايد للمراجعة.
- تعرض صفحات الحضور والبصمة، وسجل MB10، وتصحيح بصمات الجهاز الألوان والأنواع؛ كما يدعم كشف الحضور ترشيح الاستعذار، ومعاينة وطباعة ومشاركة التصنيفات.
- الاستعذار يُستنتج فقط من سلسلة `حضور → خروج → عودة` للعامل نفسه في اليوم ذاته، مع احتساب مدة الانقطاع الواقعة داخل ساعات الدوام المعتمدة (الخميس إلى 13:15؛ السبت–الأربعاء إلى 13:45؛ الجمعة مستثناة).
- الإدخالات المتكررة أو غير المصنفة أو غير المطابقة لا تُعامل تلقائيًا كاستعذار مؤكد. التصحيح الإداري لا يغيّر سجلات MB10 الخام.
- **المستحقات:** تحسب المعاينة الحالية فترات الاستعذار بعد إعادة قراءة الحركات المصححة؛ لا يوجد ترحيل تلقائي للخصم أو اعتماد مالي في هذا الإصدار. يلزم اختبار البصمات الحقيقية وسياسة الرواتب قبل تفعيل الصرف.
- هذه تعديلات على **فرع التطوير التجريبي** فقط؛ لا تؤثر على فرع `main`.


**هذا الفرع للتأسيس التجريبي فقط، ولا يغيّر النشر الحالي 0.1.3 على GitHub Pages.**

المرحلة الأولى تتضمن: هيكل D1، واجهة Cloudflare Pages Functions API، تسجيل دخول آمن، صلاحيات متعددة، شاشة مستخدمين وسجل تدقيق أولي، وإجبار كلمات المرور الأولية على التغيير. لا تتوفر قاعدة حقيقية أو خادم منشور حتى ربط Cloudflare يدويًا وإجراء الاختبارات.

**الخطوة التالية:** [دليل تأسيس وربط المرحلة الأولى](docs/PHASE1_FOUNDATION.md).

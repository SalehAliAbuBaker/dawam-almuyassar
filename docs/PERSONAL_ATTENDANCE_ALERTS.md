# دوام الميسر 0.2.13 — النطاق الشخصي والتنبيه على البصمات

## ما أُضيف برمجيًا في فرع التجربة
- «بيانات المستخدم نفسه فقط» في إدارة الصلاحيات باستخدام المفتاح `data.self_only` المخزن في جدول `user_permission_overrides` القائم من الترحيل 0006؛ حسابات `viewer` شخصية دائمًا.
- ربط كل حساب بعامل محدد عبر `employee_id` (مفتاح فريد)، وعدم الاعتماد على تطابق الاسم أو رقم الحركة. الحساب غير المرتبط لا يكشف بيانات الآخرين.
- فرض النطاق على API العاملين والبصمات والحضور والملخصات والسجلات. نطاق العرض الشخصي يمنع تعديل العاملين/البصمات أو جلب الجهاز أو فتح البيانات المالية الإدارية حتى لو كان الدور الأساسي أكبر.
- `GET /api/my-attendance?date=YYYY-MM-DD`: ملخص آمن للعامل الحالي، بتوقيت آسيا/عدن، ونهاية دوام الخميس 13:15 وبقية أيام العمل 13:45، والجمعة إجازة.
- `POST /api/my-punch-report`: بلاغ من العامل عن بصمة حضور أو انصراف أو محاولة فاشلة، يُحفظ في `audit_events` تحت `attendance.punch_issue_reported` للمراجعة؛ دون تعديل البصمة الأصلية أو الرواتب.
- صفحة `my-attendance.html` تعرض حالة العامل والتنبيهات وإرسال البلاغ، مع إشعارات اختيارية أثناء فتح الصفحة فقط. الرابط يظهر في الواجهة للمستخدم المرتبط بعامل.

## حدود الإثبات والتوقيت
- جهاز MB10 لا ينقل للنظام في البيانات المستوردة «محاولات مسح الإصبع الفاشلة». لذلك لا يثبت النظام فشل القراءة فور وقوعه.
- «بصمة غير ظاهرة» تنبيه احتمالي **فقط بعد موعد البصمة المتوقع بـ15 دقيقة** ومع وجود مزامنة ناجحة أحدث من الموعد. إذا لم تُزامَن الحركات يظهر تنبيه معلوماتي «بانتظار المزامنة» وليس غيابًا مؤكدًا.
- الحالات تشمل: غياب بصمة الدخول/الخروج، حركة غير مكتملة، تأخر الحضور، خروج مبكر أو عودة غير مسجلة، خروج وعودة أثناء الدوام، إخفاق المزامنة.
- الإشعارات الحالية داخل الصفحة، ويمكن للمتصفح عرض إشعار إضافي **عندما تكون الصفحة مفتوحة** ويمنح المستخدم الإذن. لا توجد خدمة Web Push خارج التطبيق، ولا رسائل WhatsApp/SMS تلقائية.
- التنبيهات لا تعني اعتماد خصومات، ولا تعدّل البصمات الخام ولا المستحقات. تقرير العامل لا يثبت صحة ادعائه.

## متطلبات تجربة Cloudflare
1. ضرورة وجود ترحيلَي `0005_mb10_sync_jobs.sql` و`0006_user_permissions.sql` في D1 التجريبية.
2. نشر فرع `feature/dawam-0.2.0-foundation` على مشروع Cloudflare Pages التجريبي فقط، دون مساس `main`.
3. إنشاء مستخدم بدور `viewer` مربوط بالعامل، واختبار أنه لا يرى سوى حركاته، حتى عند تعديل `employee_id` في رابط الطلب.
4. منح مستخدم `hr` نطاقًا شخصيًا، وفحص أن الصلاحيات الأوسع لا تتجاوز نطاقه.
5. تعطيل الربط وتجربة الشاشة: يجب ظهور تنبيه «الحساب غير مربوط»، دون تسريب بيانات.
6. محاكاة آخر مزامنة قبل موعد الدوام أو فشلها: يجب ظهور «بانتظار المزامنة» لا «فشل بصمة».
7. بعد مزامنة ناجحة متأخرة وغياب سجل حضور/انصراف: يجب ظهور تنبيه عدم ظهور البصمة.
8. إرسال بلاغ ومراجعة سجل التدقيق، ثم التأكد أن سجلات MB10 والرواتب لم تتغير.
9. فحص الواجهة على الهاتف، وظهور `0.2.13` تحت اسم التطبيق، واختبار منع العرض عبر API مباشرة وليس الواجهة فحسب.

## حالة الاختبار والنشر
التغييرات مكتوبة في GitHub على فرع التجربة. **لم يتم التحقق من موقع Cloudflare فعليًا، ولم تُجرَ بعد اختبارات تشغيل D1 الحية أو اختبار أجهزة MB10.** لا تُعتبر هذه الميزات منشورة أو مجرّبة ميدانيًا حتى اكتمال تلك الخطوات.

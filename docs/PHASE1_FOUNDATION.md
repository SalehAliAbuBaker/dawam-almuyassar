# المرحلة الأولى — تأسيس دوام الميسر 0.2.0 (فرع تطوير فقط)

## ما تم تجهيزه في هذا الفرع
- صفحة التطبيق نفسها من الإصدار 0.1.3 (دون تعديل النسخة المنشورة على GitHub Pages).
- migrations/0001_foundation.sql: 14 جدولًا للعاملين/أرقام البصمة، المستخدمين، الجلسات، محاولات الدخول، الإعدادات، الورديات، التوزيع، الحركات، الأعذار، العمل المسائي، دورات الرواتب، بنود المستحقات وسجل التدقيق.
- functions/api/[[path]].js: واجهة خادم D1، تسجيل دخول بجلسة آمنة، تمهيد مدير واحد، أدوار وصلاحيات، إدارة مستخدمين، حركة حضور يدوية، وتسجيل الأحداث.
- شاشة داخل إعدادات التطبيق لإدارة الحسابات وعرض سجل التدقيق في حالة الاتصال بخادم Cloudflare، مع إجبار الحسابات الجديدة على تغيير كلمة المرور عند أول دخول.

## ما ليس جاهزًا
- لا توجد قاعدة D1 فعلية ولا موقع Cloudflare Pages مرتبط الآن.
- لا اتصال فعلي بجهاز البصمة ولا حسابات رواتب نهائية أو تقارير اعتماد مالي.
- لم تُجرَ بعد اختبارات متصفح/أجهزة كاملة أو اختبارات أمنية للتشغيل الفعلي.
- نموذج الحضور اليدوي يستخدم وقتًا محليًا بلا منطقة زمنية؛ سياسة التحويل الزمني ومعالجة الجهاز تأتي في مرحلة الربط.
- هذه بنية تطبيق «جهة واحدة» حاليًا، وليست منصة متعددة الجهات.
- سجل التدقيق لا يزال أوليًا؛ يجب استكمال الذرية في جميع عمليات التعديل، وسياسة الاحتفاظ والسجل غير القابل للعبث، قبل الاعتماد النهائي.

## تشغيل تجريبي آمن على Cloudflare — دون المساس بالنسخة الحالية
1. في Cloudflare افتح **Workers & Pages** وأنشئ مشروع **Pages مستقلًا للتجربة** باسم daw am-muyassar-stage (بدون المسافة: dawam-muyassar-stage). اختر مستودع SalehAliAbuBaker/dawam-almuyassar وفرع feature/dawam-0.2.0-foundation. يكون مجلد الإخراج هو جذر المستودع عند النشر من هذا الفرع.
2. أنشئ قاعدة **D1 تجريبية جديدة وفارغة** باسم dawam-muyassar-stage-db. لا تربط أي قاعدة تخص برنامج راتب أو تطبيق العطايا، ولا قاعدة إنتاجية سابقة.
3. اربط D1 بمشروع Pages من Settings → Bindings عبر الاسم الحرفي DB، ثم أعد نشر مشروع Pages.
4. أضف SETUP_TOKEN كسر مشفر / Secret مستقل في إعدادات بيئة Pages. يجب أن يكون عشوائيًا بطول 24 محرفًا على الأقل. لا تضع السر داخل GitHub أو في محادثة.
5. لتطبيق الترحيل من جهاز به Wrangler:
   - انسخ wrangler.example.jsonc إلى wrangler.jsonc محليًا واملأ database_id من قاعدة المرحلة التجريبية الجديدة.
   - شغّل npx wrangler d1 migrations apply dawam-muyassar-stage-db --remote.
   - افحص /api/status على عنوان مشروع Pages: يرجع setupRequired=true.
6. افتح واجهة Pages التجريبية، وأكمل إعداد أول مدير باستعمال رمز SETUP_TOKEN وبريد مدير تجريبي وكلمة مرور قوية. بعد ذلك يتوقف /api/setup عن قبول تأسيس مدير آخر.
7. اختبر إنشاء عامل تجريبي وحركة حضور يدوية، ثم إنشاء مستخدم HR وآخر viewer مربوط بعامل، وتحويل الحالة إلى «موقوف» ثم الاطلاع على سجل التدقيق.
8. لا تنشر فرع التطوير على GitHub Pages؛ لا تدمجه في main قبل اجتياز الاختبارات وتوثيق إجراءات النسخ والاستعادة.

**مهم:** GitHub Pages موقع ثابت ولا ينفّذ Cloudflare Pages Functions. وجود الملفات في GitHub وحده لا ينشئ قاعدة بيانات أو خادمًا.

## واجهات API الأولية
- GET /api/status — حالة التأسيس
- POST /api/setup — تأسيس أول مدير باستخدام SETUP_TOKEN؛ يعمل مرة واحدة
- POST /api/login — إنشاء جلسة باستخدام بريد وكلمة مرور
- GET /api/me ، POST /api/logout ، POST /api/change-password
- GET/POST /api/employees ، PUT /api/employees/:id
- GET/POST /api/punches — الإدخال الحالي يدوي فقط
- GET/PUT /api/settings
- GET/POST /api/users ، PATCH /api/users/:id — للمدير
- GET /api/audit — للمدير

## آلية الحماية
- كلمات المرور تُشتق عبر PBKDF2-SHA256 مع salt فريد و240000 تكرار. لا تُحفظ كقيمة نصية.
- جلسات عبر Cookie بخصائص HttpOnly / Secure / SameSite=Strict، وتُخزن بصمتها SHA-256 في D1، وتبطل عند الخروج أو تعليق الحساب.
- فحص مصدر طلبات التعديل، وقبول JSON فقط، واستعلامات SQL محضّرة، وتقييد نطاق العامل لكل مشرف/مستخدم اطلاع.
- صلاحيات roles: admin، hr، accountant، supervisor (قسم محدد)، viewer (عامل محدد).
- الخصومات المالية غير مفعلة حتى اعتماد اللوائح، حتى لو طُلب تفعيلها من الواجهة.
- حسابات viewer وsupervisor لا تتلقى مبالغ الرواتب من واجهات الموظفين.

## معايير قبول المرحلة
- الاختبار التلقائي/اليدوي لكل مسار، خصوصًا: منع viewer من تعديل موظف أو الاطلاع على موظف آخر، منع المحاسب من تعديل الإعدادات، ومنع تكرار التأسيس.
- اختبار الجلسة بعد تعطيل الحساب، وتغيير كلمة المرور، وانتهاء الجلسة.
- اختبار بيئة الهاتف والكمبيوتر، والتحديث دون فقدان البيانات.
- سجل تدقيق صحيح لكل عملية حساسة ومراجعة الترحيلات على D1 مع خطة نسخ احتياطي واستعادة.
- عند تحقق ذلك فقط يُرفع وصف الحالة من «تأسيس برمجي» إلى «مرحلة أولى مجرّبة».

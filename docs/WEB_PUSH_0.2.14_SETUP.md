# دوام الميسر 0.2.14 — إشعارات العامل بالخلفية (Web Push)

**الحالة:** نُفذ الكود على فرع Cloudflare Pages التجريبي. لا يمكن إعلان نجاح إرسال الإشعارات ميدانيًا حتى ضبط مفاتيح VAPID في Cloudflare وتشغيل وكيل MB10 مع اتصال الجهاز وإجراء اختبار على جوال العامل. لا تغييرات على `main`.

## 1. تشغيل مفاتيح Web Push على Cloudflare Pages
المشروع المقصود: `dawam-muyassar-stage` وعنوانه التجريبي:
https://dawam-muyassar-stage.pages.dev

1. **إذا لديك مفاتيح VAPID محفوظة سابقًا، احتفظ بها ولا تُنشئ مفاتيح جديدة.** الكود يدعم المفتاح الخاص بصيغة JWK JSON أو نص base64url القياسي (32 بايت). عند عدم وجود مفاتيح قديمة، يمكن تشغيل `node tools/generate-vapid.mjs` مرة واحدة من جهاز موثوق.
2. افتح Cloudflare > Workers & Pages > `dawam-muyassar-stage` > Settings > Variables and Secrets (بيئة **Production** المرتبطة بالفرع `feature/dawam-0.2.0-foundation`).
3. أضف `VAPID_PUBLIC_KEY` بالقيمة العامة، وأضف **واحدًا فقط** من `VAPID_PRIVATE_JWK` (إذا كانت القيمة JSON) أو `VAPID_PRIVATE_KEY` (إذا كانت نص base64url) كـ **Encrypted Secret**؛ ثم `VAPID_SUBJECT` بالقيمة `https://dawam-muyassar-stage.pages.dev`. يجب أن يكون المفتاح العام والخاص زوجًا متطابقًا.
4. نفّذ Deploy جديدًا بعد إضافة المتغيرات؛ بعض التغييرات لا تدخل حيز التنفيذ إلا بعد نشر جديد. لا تُعِد توليد المفاتيح بعد الاشتراك لأن ذلك يُبطل اشتراكات الأجهزة السابقة.
5. افتح `/api/status` وتأكد من ظهور `"version":"0.2.14"` و`"pushConfigured":true`. لا يعرض هذا المسار مفاتيح أو بيانات حساسة.

**قاعدة D1:** يوجد ترحيل `migrations/0007_worker_push_notifications.sql`. وفي فرع التجربة، إن لم يُطبّق الترحيل يدويًا، تُنشأ جداول التنبيهات الجديدة تلقائيًا عند أول دخول مصرح لصفحة الإشعارات. لا يمس ذلك بيانات البصمة أو الرواتب. يتطلب نطاق البيانات الشخصية جدول `0006_user_permissions.sql` السابق.

## 2. مزامنة MB10 آليًا أثناء إغلاق التطبيق
هذا يتطلب **كمبيوتر المكتب متصلًا بجهاز MB10 عبر الشبكة**، ومتصلاً بالإنترنت، مع عمل Python و`pyzk`. خادم Cloudflare لا يستطيع الدخول مباشرة إلى عنوان MB10 في الشبكة الخاصة.

على كمبيوتر المكتب، بعد إعداد متغيرَي البيئة `DAWAM_STAGE_URL` و`MB10_IMPORT_TOKEN` كما سبق لجلب البصمة، شغّل من مجلد المستودع:

```powershell
py -m pip install pyzk
py .\tools\mb10_sync.py --ip 192.168.0.121 --agent --automatic-minutes 10
```

- يقرأ الجهاز كل 10 دقائق ويستورد الحركات الجديدة دون حذف أو تعديل في الجهاز.
- يُرسل الخادم رسالة Web Push فقط عقب **مزامنة ناجحة** وفي وقت مناسب؛ إشعار عدم ظهور بصمة الدخول بعد 07:45؛ والانصراف بعد 14:00 عادةً، أو بعد 13:30 يوم الخميس. الجمعة إجازة.
- تستثنى الإجازة اليومية المعتمدة والعامل ذو الدوام غير المنتظم. الحالات الأخرى تُعرض كمعلومات للمراجعة، لا كخصم آلي.
- إذا انقطع كابل المكتب أو انطفأ الكمبيوتر أو تعذر رفع الحركات **لا يمكن تأكيد نقص بصمة أو إرسال تنبيه موثوق في الوقت المحدد**؛ يعود الفحص عند عودة الاتصال.
- اترك وكيل الكمبيوتر شغالًا أثناء الدوام، أو شغله بخدمة/مهمة Windows مجدولة وفق سياسة الأمان بالمكتب.

## 3. تسجيل جهاز العامل
1. أدخل في «إدارة المستخدمين والصلاحيات» حساب العامل واربطه بسجل العامل الصحيح عبر `employee_id`، واختر «بيانات المستخدم نفسه فقط».
2. افتح من جهاز العامل https://dawam-muyassar-stage.pages.dev/my-attendance.html وسجّل الدخول.
3. اضغط «تفعيل تنبيهات الجوال بالخلفية» وامنح إذن الإشعارات. يُسجل اشتراك الجهاز في D1 باسم حساب العامل نفسه، وليس حسب تشابه الأسماء.
4. اضغط «إرسال تنبيه تجريبي». قبول خادم الإرسال لا يثبت ظهوره على الجهاز؛ افحص إشعارات الجوال بنفسك. يمكنك إيقاف التنبيهات من الصفحة.
5. بعض أجهزة الجوال قد تقيّد إشعارات التطبيقات بالخلفية أو توفير البطارية. لا يوجد WhatsApp أو SMS تلقائي.

## 4. حدود الضبط والأمان
- **محاولات لمس الإصبع الفاشلة لا تُرسل من جهاز MB10 ضمن سجل الحركات**، لذلك نظام Web Push يخبر العامل أن **بصمة لم تظهر بعد مزامنة ناجحة**، وليس «فشل القارئ» المؤكد.
- لا تُرسل في إشعارات Push بيانات الأجور، أو أسماء العاملين الآخرين، أو تفاصيل البصمة. يعمل الإرسال بـ VAPID وتشفير RFC8291.
- اشتراكات المتصفحات مُقيدة بحساب العامل، وتُلغى عند تعطيل الحساب أو تغيير ربطه بعامل آخر.
- يمنع تكرار التنبيه لنفس العامل والجهاز والتاريخ والنوع، ويعاد اختبار الرسالة الفاشلة حتى ثلاث مرات على الأكثر بعد المزامنة اللاحقة.
- لا تتغير سجلات الجهاز الخام أو الرواتب أو الخصومات بسبب Push أو البلاغ.
- عند زيادة الاشتراكات، تتم معالجة دفعات متناوبة حتى 20 اشتراكًا لكل مزامنة.
- لا يلزم فتح صفحة العامل لتلقي Web Push بعد الاشتراك، لكن يلزم أن يدعم المتصفح/نظام التشغيل الإشعارات بالخلفية وأن يكون الجهاز متصلًا بالإنترنت.

## 5. فحوص الإصدار
أُضيفت اختبارات `node --test tests/push-web.test.mjs` للتحقق من فك تشفير RFC8291، وتوقيع VAPID، ومنع العناوين غير المسموح بها، وفحص Syntax لملفات HTML وJS وPython في GitHub Actions. **لا نعتمد نجاح CI أو النشر في Cloudflare دون رؤية نتيجة تشغيل فعلية.**

المطلوب اختباره بعد النشر: حالة `/api/status`، تسجيل الدخول الشخصي، حفظ اشتراك Push، استلام تنبيه التجربة وجوال العامل مقفل، مزامنة MB10 تلقائيًا، ظهور التنبيه المشروط عند غياب الحركة، وعدم رؤية بيانات الآخرين، وإيقاف الاشتراك.
